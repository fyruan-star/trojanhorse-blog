Updated 2 November 2026, when the repo was reorganised and GitHub took over building the site. This is the working guide for anyone, human or AI, picking the project up. The root `README.md` is the short version for editors. `CLAUDE.md` carries the rules that always apply.

**To start a new Claude Code session**, open Claude Code in the repo folder and say:

> Work on the Trojan Horse blog in this folder. Read CLAUDE.md and docs/HANDOFF.md first, tell me the current state in five lines, then ask what I want to change.

## 4. Set up and daily commands

Editing in the browser needs nothing installed. To work locally you need Python 3 (built on 3.13, standard library only) and git. The `gh` CLI is optional and useful for watching builds.

```bash
git clone https://github.com/fyruan-star/trojanhorse-blog.git && cd trojanhorse-blog
python3 build.py                              # writes the site into _site/
python3 -m http.server -d _site 8731          # preview at http://localhost:8731/
pkill -f "http.server"                        # stop the preview
```

## 5. How the build works

`build.py` puts `content/`, `content/stories/` and `content/atlas/` on the import path, empties `_site/`, copies `assets/` into it, then runs in order: `build_index`, `build_stories_page`, `build_process`, `build_horses`, `build_weekly` for each story in `STORIES`, `build_primers`, `build_deals`, `build_desk`, `build_desk_index`, `build_buyers`, `build_atlas`, `build_katabasis`, `build_podcast`. Page templates (`HEAD`, `FOOT`, `SHEET`, `COVER`, `ROOMS` and others) live in `build.py`. It is deterministic: the line art draws from a fixed random seed, so repeated builds are byte identical.

The workflow runs the same command on GitHub with Python 3.13, uploads `_site/` and publishes it. Pull requests run the build only, so a broken edit shows a red X before it is merged. A failed build never replaces the live site.

Stylesheets: `assets/site.css` is used by every page, `assets/story.css` by deal notes, background pages and the Palo Alto stories, and `assets/atlas.css` with `assets/atlas.js` by the Atlas List. The Atlas Map is drawn in WebGL with PixiJS 8.22.0, loaded from jsDelivr (pinned, with an integrity hash) only when the Map is first opened, together with the built `tech-atlas.json`. Its files: `assets/atlas-map.js` (the Map/List switch, navigation, input, addresses, minimap), `assets/atlas-map-scene.js` (the WebGL scene: planets, sectors, focus mode, labels), `assets/atlas-map-card.js` (the player card), `assets/atlas-map-core.js` (camera, flight, label and layout arithmetic, tested with `node --test`) and `assets/atlas-map.css`. Controls, the card and keyboard targets are HTML over the canvas. Without scripts the page shows the List. Fonts come from Google Fonts (Cormorant Garamond). Colours are tokens at the top of `site.css`: navy `#303D52`, cream `#F7F4EE`, and the deeper blue `#1C2675` used for type on the white story pages.

## 7. Procedures

### 7A. Change words on an existing page

Find the page in section 6 and edit the file, in the browser or locally. In content files change only the text inside the quotation marks and keep the HTML tags. Commit, then confirm the build is green and the page is live (section 11).

### 7B. Add a new Trojan Horse story

1. **Research first.** Read the primary documents (filings, releases) and note every figure with its source. Note what you could not read. Section 9 has the evidence rules.
2. **Create `content/stories/<name>.py`** by copying `uber.py`. Required names:
   - `WEEK`: the display date, for example `"1 November 2026"`.
   - `SLUG`: the page name without `.html`. It must be unique.
   - `KICKER`: `"Trojan Horse of the Week"`.
   - `TITLE`, written with HTML entities (`&amp;`, `&rsquo;`).
   - `HOOK`: one sentence with a concrete number or tension.
   - `LOGO`: see step 3.
   - `GO`: `(href, label)`, the closing link on the story page. Each story currently links to the previous one.
   - `SECTIONS`: a list of `(heading, [paragraph, ...])`. Paragraphs are raw HTML. An empty heading renders running prose with a larger first paragraph.
   - `NOTE`: the sourcing note under the story. Say where figures come from, what could not be verified, which numbers are your arithmetic, and which people are invented.
3. **Get the logo.** Take it from the company's own site (view source for the header `<svg>` or an `<img src="...svg">`), or from Wikimedia Commons when the site hides it. Uber's header draws its mark in CSS, so its file came from Commons, where it is tagged public domain and flagged as a trademark. Before use, open the file and confirm it has no `<script>`, no `on...=` handlers, no `<foreignObject>`, no `<image>` and no external `href` or `url(http`. Save it as `assets/images/logos/<name>.svg` and set `LOGO = {"file": "<name>.svg", "w": <viewBox width>, "h": <viewBox height>, "name": "<Company>", "height": <px>}`. Choose `height` so the rendered width lands near 100 to 135 px (Oura 34, Thorne 20, Uber 34). The mark renders as a one-colour mask, silver on the homepage and navy on the story page, so it never needs recolouring. Logos are the companies' trademarks, used only to identify the subject.
4. **Add `"<name>"` to `STORIES`** in `content/home.py`, in the position you want on the homepage.
5. **Preview** the homepage and the story at about 1280px, 900px and 375px. Below 900px the cards stack.
6. **Audit** with the snippet in section 11.
7. **Commit** the story file and the logo, push, and confirm the build and the page.
8. Optionally point the neighbouring story's `GO` at the new one.

### 7C. Reorder, hide or retire a story

`STORIES` controls both the homepage order and which story pages are built. Reorder it to reorder the cards. Removing a name takes the story off the homepage and also stops publishing its page, because the site is rebuilt from scratch each time. If the URL was ever shared, add a redirect first (see `build_stories_page` for the pattern).

### 7D. Podcast page

`EPISODES` in `content/home.py` is a list of `(title, description, status)`. There is no audio yet. The Spotify mark on the homepage links to `podcast.html`.

### 7E. CSS changes

`assets/site.css` section headers, in file order: TOKENS, COVER, TALE, SPOTIFY, THE BELT, FOOTER, RESPONSIVE, THE PICKER ON THE COVER, SILO HEADER, DEFINITION, PODCAST, FIRST PRINCIPLES, KATABASIS, GROUND FLOOR, THE WHITE PLATE, THE PROCESS RAIL, TROJAN HORSES (older, now unused), THE JOURNAL INDEX, LINE ART, TROJAN HORSES (current). The homepage stories are the `.th*` rules, the logo masks are `.th__logo` and `.plate__logo`, and the white story pages use `.plate`, `.white`, `.wp` and `.ch`. Stories stack at 900px. About 76 of 189 class names in `site.css` are used by no page (section 12), so check built pages before deleting any rule.

### 7F. Deal notes, background pages, Palo Alto stories

Each is a dictionary in its content file with a `slug`, title lines, sections and sources. Prologue entries find their deal note by title through `DEAL_LINKS` in `build.py`. Follow the existing entries for shape.

## 9. Editorial standards in full

The rules in `CLAUDE.md` are the short version. The detail behind them:

**Structure.** State the thesis early and plainly. Present the prevailing view fairly and name whose view it is, then give the alternative reading in concrete terms. Each paragraph sets up the next. Make load-bearing assumptions explicit. Use a concrete example for each abstract claim and label hypotheticals. Address the strongest counterargument and say what evidence would decide it. End with the practical implication.

**Evidence hierarchy.** Use the company's own filings first (S-1, 10-K, 10-Q, 8-K), then releases from the company or its counsel, then established financial press, then trade press. Commentary and aggregators may be cited only with attribution to what they report. Read the document yourself. Summaries have been wrong here: one gave a different use-of-proceeds figure from the filing, one claimed a Customs ruling that could not be confirmed, and the owner's own notes made a claim about Waymo that the record narrows. SEC pages are huge and fetch tools truncate near 450,000 characters, so late sections such as the principal and selling stockholders table may be unreachable. Say so when that happens.

**Numbers.** Label your own arithmetic. Give a range when outlets disagree. Never present a figure you did not see in a source.

**Quotes.** At most one direct quote per Trojan Horse story, under about 15 words, attributed and linked. Paraphrase everyone else and link them.

**Privacy.** Do not name private individuals who supplied information for a piece.

**Story register.** See `CLAUDE.md`. The owner rejected two earlier Oura drafts: the first never named the horse, and the second was eleven separate findings that read like a walkthrough of the filing. The accepted version has eight chapters, names the horse early, and follows one idea through the numbers (every dollar in an IPO has a return address).

**Older pages.** The process page, the Prologue, the Palo Alto stories and the Atlas use a plainer, argument-first register. The Trojan Horse stories are the one place where humor and analogy are wanted.

## 11. Verification and deploy

**Audit the pages you changed** after a local build, for banned punctuation and quote count:

```bash
python3 - <<'PY'
import re, html, pathlib
PAGES = ["index.html", "oura-ipo.html"]          # list the pages you changed
for f in PAGES:
    t = (pathlib.Path("_site") / f).read_text(encoding="utf-8")
    m = t[t.index("<main"):t.index("</main>")] if "<main" in t else t
    b = html.unescape(re.sub(r"<[^>]+>", " ", m))
    quotes = len(re.findall("“[^”]+”", b))
    print(f"{f:26} em dashes {b.count(chr(0x2014))} | semicolons {b.count(';')} | question marks {b.count('?')} | direct quotes {quotes}")
PY
```

Em dashes and semicolons should be 0, and a story should have 1 direct quote. A story's closing link adds a question mark when it points to the Thorne story, whose title ends in one.

**Check internal links:**

```bash
python3 - <<'PY'
import re, pathlib
site = pathlib.Path("_site")
have = {p.name for p in site.glob("*.html")}
bad = [(p.name, h) for p in sorted(site.glob("*.html"))
       for h in re.findall(r'href="([^"#?:]+\.html)"', p.read_text(errors="ignore")) if h not in have]
print("broken internal links:", bad or "none")
PY
```

**Watch a push go live:** `gh run watch` follows the build. A green build has published. Then confirm with curl:

```bash
curl -s https://trojanhorse.blog/<page>.html | grep -c "<a string from your change>"
```

**If the build is red**, open it on the Actions tab and read the failing step. It is almost always a syntax error in a content file, such as an unclosed quotation mark or bracket. The live site keeps the last good version until a build succeeds. To republish without a change, run `gh workflow run publish.yml` or use **Run workflow** on the Actions tab.

## 13. Lessons from the build

- Built HTML is never committed now. Edit `content/` or `assets/`, never `_site/`.
- `git add -A` has swept in another session's work. Stage by name.
- A plain string containing `{NAME}` leaked the braces into a page once. Use f-strings only where a line has a placeholder.
- An unquoted shell heredoc runs anything in backticks as a command. Quote the delimiter (`<<'EOF'`) when the text contains backticks.
- Checks can report false confidence when the string you test for is not literally in the file. Read back the thing itself.
- A long document truncated by a fetch tool looks complete. Check what range you actually read.
- Screenshots lag. Measure.
- The owner reads the live site, so an unpushed change is an invisible one.
